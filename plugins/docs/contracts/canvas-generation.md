# 画布生成契约

本页是客户端画布的选择、素材、执行和恢复规则。网关负责发布账号可用的模型、组、组价、协议及能力。执行中枢是客户端读取目录、处理协议和提交任务的唯一入口。画布和 Agent 通过同一份目录和执行规则工作。[网关模型契约](https://github.com/omnimux-ai/omnimux-gateway/blob/main/docs/model-governance/CONTRACT.md) · [中枢开发指令](../../plugins/omnimux/AGENTS.md) · [Agent 工具契约](plugin-agent-tools-inventory.md#36-omnimux-workflow工作流无限画布)

## 状态与适用范围

已有模型目录、已保存任务恢复、操作 ID 和 `modeKind` 本地化继续按现有契约工作。客户端在账号目录发布组能力时应用下文规则。网关覆盖范围和可用状态以目标环境的验证为准，见[当前任务规格](../../../specs/canvas-group-capabilities.spec.md)和[网关 #74](https://github.com/omnimux-ai/omnimux-gateway/issues/74)。独立图像生成面板有自己的交付范围。

## 目录和协议

- 网关快照决定官方模型的可售成员。中枢负责判断当前账号、分组和客户端实现支持度。官方模型沿用已支持的协议、操作、素材角色及参数类型时，刷新目录即可纳入。新增模型 ID 无须增加本地白名单、构建产物、请求地址或素材字段例外。
- 中枢按 `/api/pricing` 每个模型的 `group_order` 排列在售线路。未列出的在售线路按 `enable_groups` 到达顺序补齐。`default_group` 在当前可用时投影为相应线路的 `default: true`。只有缺少 `default_group` 时，才从 `group_order` 读取第一条可用线路。空字符串明确表示无默认。无效的显式默认也不给任何线路加默认标记，并在刷新日志中记录。
- 网关的 `effective_video.groups` 以实际提交的组键为索引，每组包含一组完整的操作变体。中枢将分组价格与该组的 `effectiveOperations`、`effectiveVersion` 一并投影。模型名称和 `modeKind` 用于显示，提交使用原 operation ID。
- 每个候选必须同时满足一种完整变体的方式、必需素材、数量和参数。某变体的低价、默认值或素材范围不能与另一变体的参数拼接。中枢按有效变体的已支持协议提交，变体可声明 `gateway_protocol`，协议一致时继承模型级同名字段。未知协议、必需输入类型或参数类型的候选隐藏。同一模型的其他可用候选继续提供。
- 网关字段缺省表示没有组级发布，旧目录可走已验证的兼容入口。发布存在但组缺失、组为空或没有客户端支持的变体时，该组在新入口不可选。旧规则、其他账号快照和默认模型参数不能补出缺少的组能力。
- 目录身份、价格和能力必须成组更新。账号切换、退出或组权限撤回后，上一账号的响应不能重新打开选项。提交时重新确认当前组仍可用。失效时保留草稿并让用户重新选择。
- 已被新登录或退出替代的账号校验及登录请求不能写回旧身份，也不能把新账号标记为过期。

当目录含登录账号可用分组时，中枢 `GET /omnimux/model-catalog` 和画布 `GET /omnimux-workflow/api/capabilities` 都校验本机 Host 授权和请求来源，成功响应使用 `Cache-Control: private, no-store`。缺少授权、来源不符、授权服务不可用时返回相应的 401、403、503，画布须清空失效选项并按当前账号重新读取。匿名目录继续提供公开模型信息。

中枢发现目录变化时，通过现有 Host 连接通知已打开的画布重新读取。通知不包含账号或目录数据。画布立即清空旧选项，忽略被替换的请求结果并保留节点草稿。连接恢复后重新读取一次目录。

## 选择和素材

- 用户选择模型和分组；视频节点选择生成方式。图片节点的生成方式由参考图槽派生：本轮消费 0 张参考图提交 `text_to_image`，消费 ≥1 张参考图提交该模型消费参考图的已上架 operation（`image_to_image` / `multi_reference`）。图片节点不再单独提供文生图/图生图选择控件。可选控件只展示该账号和客户端支持的候选。使用已知的零素材方式或者可先选后填的首帧、首尾帧方式。必需槽位为空时显示空槽，提交前再校验必需输入。
- 打开包含网关分组选项的品牌会展示该品牌的型号。切换模型时采用目录标记的可用默认线路。模型有线路但没有可用默认时，先选择具体线路，再保存模型和线路。只有一条可用线路时也遵循同一规则。仍可用的手选线路保持选中。
- 换模型进入所选组发布的默认方式。换组时保留目标组仍支持的当前方式，否则使用新组的默认方式。组内只有一种方式时可直接选定。有多个方式且没有默认值时，由用户选择。换模型、组或方式后，各参数取新组合的默认值。没有默认值而又有多个合法值的必填项由用户选择。
- 开关参数按当前组和方式声明的布尔值显示和提交。例如网关允许用户调整声音时显示有声开关，网关固定声音时沿用固定值。
- 同用途的参考素材共用一个添加入口。选择器按当前输入类型、格式和剩余容量装填，所有参考槽满后隐藏入口。首帧、尾帧、角色图和驱动音频等独立用途使用命名卡槽。上游文本从提示词区引用。
- 素材按用途和顺序保存在节点草稿中。切到更小的容量只展示可消费的部分，切回恢复可用素材及顺序。普通参考素材不会自动改为首帧。通用连接提供候选。它不锁定具名槽位，也不屏蔽已支持的方式。一般连接、断开及素材重排不改变用户已选的方式。旧项目重开、撤销和复制应保留合法草稿。每次手动切换模型、分组或方式各保留一个撤销步骤，撤销后恢复上一步的参数与槽位。
- 当前未被消费的素材退出本次请求，包括对应的 `@` 引用、参数输入和隐式上游执行。保留边和草稿供下次切换。执行范围中用户直接指定的节点仍属于运行请求。

## 执行和恢复

- 模型菜单、运行前检查、请求构造和子图生成使用同一选择结果。新任务只发送当前选择的组。参数、槽位、默认值和协议均来自该组选定组合。协议对应的提交地址、素材映射和查询地址在中枢处理。
- 共享检查覆盖 UI、Agent 和无界面任务。按节点查询可选项时使用相同目录投影和同一组版本。执行尚未结束时按返回的执行 ID 查看。已受理任务以原任务 ID、归属和记录的协议查询，不随刷新或组切换重提。
- 普通图片及视频生成的空提示词由上游网关判断。执行准备仍校验当前组合要求的角色素材、外部文件和其他参数。
- `workflow_node_update` 使用与画布相同的分组切换和默认值规则。当前组合内可单独调整参数。新参数须一起匹配同一变体，线路报价过期时须从节点快照读取新报价后再提交。
- 成功的模拟任务、真实网关试验以及实际 Dev 界面是不同证据。只有受权的真实调用能证明实际线路执行。旧任务恢复、自备渠道以及未消费组级数据的调用端按各自的兼容契约验证。

## 跨仓验证与交接

- 网关从实际目录输出生成合成样例。客户端以固定提交、协议版本和样例摘要消费副本。样例用合成账号、分组、素材和价格，双方公开工作流均能离线验证。任何上架、协议或示例变更都核对旧客户端兼容和同版本中英文接口文档。[当前固定样例](../../plugins/omnimux/src/catalog/testdata/gateway-grouped-video/README.md)
- 客户端从仓根运行 `node --test plugins/scripts/verify-agents-md.test.mjs` 检查现行规则入口及历史替代链接，运行 `corepack pnpm --dir plugins run verify:model-contracts` 对账目录并走回归。行为验收固定客户端构建，添加未见过的模型 ID，验证可选、提交、查询和成片，检查同 ID 多组、无权组、未知协议和提交字段。真实视频调用按任务授权执行。
- 任务的两仓 Issue 和 PR 相互引用。接手以工单里的目标、关键取舍、验收编号、双方提交、协议和样例版本、运行构建、实测结果、待验证项及授权范围为准。合入、物化和 Dev 验收分别记录。使用干净检出复核当前规则和命令，留存公开摘要，内部证据按仓库边界保存。[跨会话交接规则](https://github.com/omnimux-ai/omnimux-gateway/blob/main/.agents/rules/development-workflow.md#换会话后如何继续) · [客户端交付](../../README.md#本地开发与交付)
