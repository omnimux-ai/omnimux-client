# UI 分类标签与短文案命名规范

本契约定义 OmniMux 界面中一级场景分类、筛选胶囊、Tab 页签、卡片分类徽章及下拉首项的命名原则与验证门槛，作为产品 UI 文案与回归门禁的单一真源。

## 适用范围

- 技能广场与创作工坊场景筛选胶囊（`scene-*`）
- 会话输入栏技能选择器（`SKILL_SHELF_TAXONOMY` / 预设分类 Tab）
- 详情抽屉与推荐卡片中的分类徽章、分区标题与状态筛选首项

## 核心原则

1. **字数硬预算与同排节律**：一级分类与筛选胶囊中文标签控制在 **2–5 字**，同一水平栏并列胶囊优先统一为 **4 字**等长节律，避免参差换行与窄屏横向溢出。
2. **禁用「A与B」并列拼接，用上位词收敛**：禁止在标签中使用 `与`、`和`、`及`、`、`、`/`、`·` 拼接两个子主题；需要拼接往往说明抽象层级过低，应向上提炼覆盖全桶的单一上位词。
3. **语义覆盖桶内全员并去除冗余限定词**：命名必须逐项核对分类下的全部成员，不能以偏概全（如涵盖分镜与电影运镜时用 `视频创作` 而非 `短视频创作`；同时包含选品与社媒分析时用 `市场洞察` 而非 `选品洞察`），删除不增加区分度的前缀或后缀。
4. **展示文案与稳定 ID 解耦，多源单一真源**：内部标识（如 `scene-video`）保持稳定，调整展示文案时不改路由与筛选逻辑；同步刷新目录标签（`subtitle` / `tags`）、`i18n`、卡片徽章词典、精选快照（`featured-skills.json`）与随包 `SKILL.md` / `meta.yaml`，并由单测守卫跨模块一致性。
5. **双语平行精炼与基础文案红线**：英文标签使用 1–3 词行业惯用短语，不直译中文复合结构；界面文案禁止使用中点 `·` 作为分隔符；下拉筛选首项固定为 `全部`（不写 `全部+维度`）。

## 标准命名四步法

1. **盘点全员能力**：先列出该分类下全部条目及其真实输入/产出，划定完整语义边界。
2. **提炼单一上位词**：用最凝练的动宾或行业词概括整组能力，消除 `A与B` 拼接与冗余定语。
3. **对齐同排节律与双语**：横向对比同排所有标签的字长与视觉平衡（中文优先 4 字，英文 <= 24 字符）。
4. **反查与门禁固化**：核对每条成员与新标签无语义偏差，验证窄屏/亮暗主题无截断溢出，并将字长与多源同步规则写入自动化测试。

## 正反例对照

| 场景 / 维度 | 改前（反例） | 改后（正例） | 英文正例 |
| --- | --- | --- | --- |
| `scene-video` | 短视频创作（限定词过窄） | 视频创作 | Video Creation |
| `scene-replicate` | 爆款复刻与再制（7 字双主题拼接） | 爆款复刻 | Viral Replication |
| `scene-visual` | 商品视觉与海报（7 字双主题拼接） | 商品视觉 | Product Visuals |
| `scene-research` | 选品与社媒洞察（7 字双主题拼接） | 市场洞察 | Market Insights |
| `scene-growth` | 投放与增长运营（7 字双主题拼接） | 营销增长 | Growth Marketing |
| `scene-tools` | 剪辑与效率工具（7 字双主题拼接） | 效率工具 | Editing & Tools |

历史收敛先例：输入栏技能选择器 4 字等长分类与动宾短名规范见 [Skill Picker 四分类收敛规格](../../../specs/skill-picker-naming-taxonomy-337.spec.md)。
