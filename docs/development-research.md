# 需求确认后的研究与决策

协调 Agent 从已确认的用户任务出发，先查案例、数据和真实性，再选方案。研究、演示和评审都可以委派，协调 Agent 对最终选择和验收负责。

## 定方案前留下什么

在已有任务规格或工单记录研究依据，插件任务可沿用规格里的“假设”和“证伪方式”。无需规格的轻量任务可先记在任务对话，再在 PR 说明中摘要。进入公开仓的规格、工单和 PR 均只写可公开的事实与来源，原始内部数据留在获准的位置。

1. **案例与来源。** 写明用户要完成的动作、当前受阻点，以及参考案例里与这个决定有关的具体行为。附可重找的页面、版本或提交及文件位置。来源暂不可用时，改查官方文档、公开源码或本仓可复现案例，注明证据能支持到哪一步。
2. **数据与真实性。** 记录观察条件、样本和结果。能量化时记录有意义的基线，例如同一任务的操作步数、错误出现次数或完成耗时；交代样本量、环境和测量口径。分清亲手操作、源码或示例所示、厂商自述及待验证推断。没有可信数据就写未知和验证方法。一次演示不能推出成功率、转化率或节省时间。
3. **取舍与验证。** 写出采用什么、为何适合本仓、哪项证据会推翻它，以及对应的用户动作和通过条件。有实际备选时说明放弃理由。协调 Agent 核查足以改变选择的依据；有分歧时先做最小可逆试验。研究结论不得自行扩大功能范围或降低已确认的成功标准。

例如，为“整理素材后仍能追溯来源”选方案时，可用 MiniMax 示例的两个节点和一条连线构造对照。先在 OmniMux 记录现状，按任务范围执行整理动作，再核对素材、位置与连接。示例提供了测试输入；要声称新版更快，还须在可比条件下测量改前和改后。

## 从演示验到合入版本

- **演示评审。** UI 改动先做可打开的高保真前后对照。Agent 操作同一任务，查看主操作和素材是否有清楚的视觉顺序、布局是否对齐、键盘焦点是否可见，以及窄屏、亮暗主题、打开的浮层和相关的等待或失败状态。发现问题就修改演示，满足已确认需求后自行实施。
- **运行验收。** 在候选版本的真实入口复走同一任务，比较演示和实物。静态画面用同场景截图核对；拖拽、切换、连续编辑等用操作序列与前后状态，必要时附短录像。留存实测版本、输入和实际结果，区分夹具、真实运行和真实业务调用。内部证据保存在获准的位置，公开 PR 只放可公开的摘要和引用。
- **合并与交付。** PR 中可追溯到研究决定和验证结果。协调 Agent 核查后按[合并与复核](../AGENTS.md#合并与复核)交付，修复失败并复测。对外发布、生产写入或其他超出任务的授权继续单独处理。
