数据源追踪

从 manifest → page 分片 → 卡片渲染的完整链路
层级实际数据 / 行为结论
manifest.json material.sub_categories 中 hook 为 705 条 / 30 页；素材分类共 855 条。 列表数据存在，问题不在分页或分类过滤。
material/hook/page-0000.json 首屏 24 条：24/24 条 cover_url 为空，且无 thumb_url；其中 23 条为 video 并带可访问的 MP4 media_url，1 条为纯描述行。 数据源只给视频文件，没有封面图。
全量钩子行 705 条中 696 条 video、9 条 other；仅 2 条有 cover_url，其余 703 条无任何封面。 不是个别坏行，是整个分类的封面数据缺失。
CloudTileMedia 无封面 → bareClip = true → 渲染 <video class="...preview--bare">；该 class 继承 position:absolute; inset:0; height:100%。 视频本应作为卡片正面，但脱离文档流。
卡片 CSS .cloud-card--media .cloud-thumb { height:auto; min-height:0; }，容器内只有绝对定位视频 → 实测 thumb 高度 0px、卡片高度 50px。 最终只剩标题，与截图一致。
修复策略 无封面视频改为文档流内首帧（视频自身宽高比撑开卡片），加载元数据后 seek 到 0.001s 解码首帧；不改变有封面卡片的图片优先路径。 首屏 24 条都会显示画面，且不额外请求不存在的封面图。
备注：本次演示使用 cloud-catalog/material/hook/page-0000.json 的真实名称与 MP4 地址； 修复前卡片按当前源码的真实几何（0px 缩略图）复现，修复后按建议实现渲染。
