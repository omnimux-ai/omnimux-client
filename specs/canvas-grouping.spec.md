# 画布分组、收起和解体

## 需求

修复组内节点在收起后解体时从画布消失，以及已收起的组重开后错误显示组内节点。保留节点内容、位置和真实连线。按钮、快捷键、撤销和重做应对同一分组状态给出一致结果。

## 现状与参考

- 在隔离应用的三节点项目中，组外 C 连到 A，组内 A 连到 B。已保存的收起组刷新后仍显示为收起，A 和 B 却重新可见并叠到展开按钮上。收起状态下点「解体」时，保存仍有三个节点及两条原始线，实时界面只显示 C 并留下悬空线。刷新后 A 和 B 才恢复显示。
- 移动后展开解体的对照与存档核对均显示两个组内节点的绝对位置正确。此次修复以该已有行为为基准。
- 本地 MiniMax Design 4.0.16 的随包契约描述了解体保留组内节点及绝对位置。随包示例能核实节点与来源连线。收起后的连线表达未在 MiniMax 实机验证。[产品说明](https://design.minimax.io/en)
- React Flow 的展开和收起示例以完整图为输入，按可见性绘制；子流程文档描述了组内相对坐标。ComfyUI 用独立组端口呈现跨组线。本次以现有组框为边界，收起期间隐藏连接到不可见节点的线，展开或解体时恢复它们。存档继续保留原始端点、方向和端口。[React Flow 展开和收起](https://reactflow.dev/examples/layout/expand-collapse) · [子流程坐标](https://reactflow.dev/learn/layouting/sub-flows) · [ComfyUI 子图](https://docs.comfy.org/interface/features/subgraph)

## 假设

以节点的实际分组归属及组的收起状态计算画布可见性，就能让编辑、重开、撤销和重做呈现同一个图。撤销记录在每次有效的分组操作完成时形成。画布保存格式和真实连接沿用现有契约。

## 证伪方式

在隔离应用用同一份三节点夹具走完下列操作，每次核对可见节点、原始边及保存后的坐标和内容。若按钮和快捷键结果不同、重开与保存前不一致、撤销跳过分组状态或出现无可见端点的连线，即判定失败。

- AC1 框选 A、B 并打组，拖动组。A、B 同步移动，C 的位置不变。
- AC2 从展开和收起状态分别解体，覆盖按钮和快捷键。A、B 在移动后的绝对位置立即可见，素材和连线保持。收起期间观察组内线及跨组线无悬空。
- AC3 保存收起状态并重开，组内节点仍隐藏，展开按钮可操作。解体后重开与即时显示一致。撤销恢复上一个分组状态，重做恢复刚完成的状态。
- AC4 以同一场景的可打开演示比较改前和改后。隔离应用验收覆盖亮色、暗色、窄画布、打开的组工具栏。候选和合入版本分别核对加载产物并复走实际操作。

## 旧标准变更

- `plugins/plugins/omnimux-workflow/src/canvas/editor/utils/groupVisualMath.test.mjs` :: `planToggleGroupCollapse: 收起组并隐藏子节点，再次触发完整展开还原`

旧用例从编辑数据中读取临时的隐藏标记。持久化会省略该标记，造成当前画面与重开不一致。新用例继续验证收起尺寸、展开尺寸和组内节点隐藏与恢复，并从生产画布投影读取可见性。项目保存与重开的回归另外验证原连线以及解体后坐标。
