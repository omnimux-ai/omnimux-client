# 画布提交与恢复

## 目标

统一当前操作对素材和文本的判断。同一执行调用只做一次工作流提交校验。旧图显式清空、固定、停用和已有任务取回保留各自语义。

## 假设

同一组素材经 HTTP、Agent 或无界面入口启动时得到相同结果，已有受理任务可按原标识取回。

## 证伪方式

用同一张图和同一份目录分别走三个入口。任何拒绝原因不一致、取回时重新提交或模型下架后无法取回都视为失败。

## 验收

校验原始调用、画布、Agent 和无界面运行。画布按同一视频节点连续操作，覆盖亮暗主题、窄屏和打开的生成方式菜单。

## H3 对口型

| 同一节点上的操作 | 应看到的结果 |
|---|---|
| 在官方目录中手动选择「数字人/对口型」 | 可在添加素材前选中该方式。已有的「角色图」和「驱动音频」各接收一个素材。 |
| 仅选一项，或把另一项设为待命 | 生成按钮说明仍需补齐的素材。图和音频均可用后允许提交。 |
| 在对口型模式编辑或清空提示词 | 草稿始终可编辑。依据网关发布的该操作，只提交选中的图和音频。 |
| 切回「文生视频」，编辑草稿后再次选「数字人/对口型」 | 两种方式显示同一份最新草稿。文生视频运行时忽略对口型的两个素材槽。再次打开对口型时，先前选定的角色图和驱动音频恢复，待命素材仍是待命。 |
| 执行期间再次点击生成 | 同一次执行期间按钮保持忙碌状态。 |

手动选择的行为适用于网关已声明无文本对口型的模型的这两种操作。来源目录未提供完整声明时，旧图仍使用原有兼容规则。运行时核验的是本次将消费的素材，未被对口型选用的文档不会参与检查或改写时长。

## 规则归属与旧数据

- 画布呈现当前操作能接收的素材与阻塞原因。HTTP、Agent 和无界面执行用同一份启动结果决定是否排队。
- 排队期间目录或上游产物可能变化。派发时用当次实际后端的目录核对即将提交的素材；直接调用网关也走该校验。
- 已受理且符合恢复条件的任务按原标识取回。旧版本分别记录过原始工作区和整理后的执行子图，读取时按已有证据匹配。无法证明仍是同一输入时向调用方返回原任务线索。
- H3 对口型已取得上游任务编号，且执行记录确认提交时省略了节点提示词时，仅修改该节点的提示词草稿，重试仍取回原任务。更换角色图、驱动音频或其他生成参数会重新判断。同一项目文件原路径被覆盖时，根据原文件内容摘要识别替换。文件已移除时可按原单号取回。旧记录缺少项目素材摘要而无法核对修改时，提示查看原单号。缺少这项提交证据的历史记录继续按原输入匹配。
- 画布加载与执行准备使用相同的旧版 H3 槽位映射，保留手动选中的来源、固定关系、待命状态及留空的当前槽。新生成的记录标明输入摘要的来源，后续版本无需再推测其格式。保存的旧工作流仍受支持期间，保留读取兼容。
