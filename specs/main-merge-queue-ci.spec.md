# main 合并队列的必需检查

## 范围

为现有 CI 工作流增加针对 main 的合并组检查事件。原有 PR 和 main 推送入口、四项 CI 检查以及独立质量检查流程继续使用。

恢复生命周期检查原有的工具脚本边界，识别单仓迁移后的 `plugins/scripts/`。插件产品源码仍检查生命周期，工具脚本的语法与安全扫描继续运行。

## 假设

合并队列在候选提交触发独立的合并组事件。GitHub Actions 的 checkout 使用该事件的提交，四项既有检查可以验证准备合入的代码。

## 证伪方式

检查五个受保护状态仍有同名任务、触发器只匹配 main，并在队列启用后确认 GitHub 为真正的合并组提交报告五项成功结果。普通 PR 的成功结果不能替代合并组结果。

运行队列使用的插件全量扫描，确认旧路径导致的 18 项工具脚本误报消失。回归测试须证明产品源码仍能触发生命周期失败，并且工具脚本仍会触发语法和安全失败。
