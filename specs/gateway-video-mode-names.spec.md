# 视频生成模式按网关契约命名

当前画布借助图片槽位上限把同一个视频操作显示为「双图参考」或「多图参考」。已打开的 Dev 画布显示「多图参考」，同版本 Muse 网关契约使用 `video_multi_ref` 作为可执行操作 ID，用 `image_reference` 表达模式语义。网关契约将 `multimodal_reference` 用于 Seedance 的全能参考。可核对[网关操作定义](https://github.com/omnimux-ai/omnimux-gateway/blob/a203d5a88/docs/model-governance/CONTRACT.md#L295)。

客户端在 Hub 目录和画布投影透传 `modeKind`，显示层复用统一的本地化入口。已知语义的文字稳定，图片数量仅参与校验。缺字段的旧目录继续使用原有操作名回退。删除按槽位数量选择模式名的分支。保留执行操作 ID、槽位、线路过滤、参数和旧项目配置。逐线路能力数据的新增消费单独安排。

验收使用同一视频节点打开模式菜单并检查底栏。Muse 固定 2 张与 2–10 张均显示「图片参考」，Seedance 全能参考显示「全能参考」。在无素材的同一节点上切换图片参考与文生视频，菜单选中项与底栏一致。首帧驱动名称可见，并遵循该节点现有的素材兼容状态。窄屏与亮暗主题下菜单可打开，模式名称完整。目录刷新只改模式语义时，画布可识别新目录。测试不提交真实视频生成。
