# 隔离 Dev 的默认凭据

桌面用同一个入口初始化发行版、Dev 和自定义数据目录。旧实现对所有目标都执行从共享 Harness 目录迁移设置和凭据的兼容逻辑。用单独的目录做验收时，只要缺少本地凭据，仍会读共享目录。

默认正式版目录保留原有迁移。Dev 和自定义目录首次使用发行默认设置与本地空凭据。已有普通本地文件原样保留；已有设置或凭据链接时停止初始化。凭据文件采用仅在不存在时创建的写入方式，避免并行初始化覆盖本地登录。空映射由固定版本的 Harness 凭据加载器支持。[Node.js 文件创建标志](https://nodejs.org/api/fs.html#file-system-flags)

## 验收

- 构造可读取的合成共享设置和凭据。旧版本复制它们，新版本初始化 Dev 和自定义目录时读取尝试为零。本地凭据是空映射，设置使用发行默认值。
- 已有普通本地凭据保持原样。重新初始化缺少凭据的已有隔离 Profile 时，重新创建空文件。共享凭据的链接被拒绝。
- 用全新验收用户目录、工作目录和有限启动环境，按桌面入口启动实际 Dev。验收进程对真实共享目录只做系统拒读保护，不接收任何真实凭据。验证安装、启动和匿名状态都能完成。
