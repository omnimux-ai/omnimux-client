# Muse 双图参考画布对齐

## 现状与依据

生产目录的 `muse-video` 双图参考要求恰好两张 JPEG、PNG 或 WebP，第一张用于起始画面。网关已接受现有客户端的有序 `image_urls`。Dev 画布目录将下限从 2 投影为 1，也遗漏首项用途，因此单张图可能被判为可提交，用户无法在槽位里确认和调整首图。[网关实现与模型页实测](https://github.com/omnimux-ai/omnimux-gateway/pull/54)

已验收的模型页以两张缩略图和一个交换按钮表达顺序。画布沿用自身的素材槽、缩略图和选取器。现有首尾帧提供交换按钮和键盘可访问名称，双图参考复用该交互表达。换序只调整同一业务槽内的素材顺序。在线与内置回退目录使用 Muse 的同一份网关契约。

## 实现与验收

- AC1 画布使用线上同形的合成契约。打开存有两条候选连线的单图首帧节点，首帧模式与生效图保持。显式切换单双图时沿用当前选定的起始图。
- AC2 双图模式只有一张可用图时，显示可补齐的素材槽并禁用生成。补图保留起始图，按槽替换保留图片的位置，相连提示词仍可预览和编辑。界面、工作流执行入口和 Hub 使用相同的张数约束。
- AC3 第一张缩略图标明起始图。交换后实际有效素材和发送次序同时变化，原连线保持。保存重开后沿用交换后的顺序，撤销恢复前一个顺序。
- AC4 从同一节点经 UI 与 Agent 使用同一变更规则。顺序已变化时，过期的交换请求不再次交换。隔离环境对照两种模式的请求，双图按显示顺序使用参考图集合，首帧使用单图。
- AC5 操作版前后对照演示先行。候选版与合入版均在隔离环境核对构建来源、模式浮层、亮暗与窄屏，并从画布入口检查上述动作。视频实测采用合成素材和本地模拟上游。
