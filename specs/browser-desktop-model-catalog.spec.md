# 浏览器伴侣模型目录与桌面对齐

## 现状与依据

浏览器伴侣设置的两个菜单各自在挂载时尝试加载当前实例的模型目录。配对握手还未完成时，请求失败后会降级到发现接口的订阅目录，连接恢复也不触发重新加载。隔离宿主还复现了另一个故障。扩展完成握手后，事件桥接缺少当前 DSH 版本要求的调用上下文，连接在模型目录返回前关闭。本机发现接口的只读抽样返回两个订阅分组，与报告中的菜单一致。

参照 [DSH 桌面模型选择契约](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-model-selection/README.md)与本仓固定 DSH 版本的实现，复用桌面使用的 Host 模型目录和渠道、模型二元标识。保留浏览器伴侣设置行和原生下拉。进入设置、面板重新获得焦点及连接切换时，两个菜单共同读取一次当前已认证实例的目录。加载失败或空目录有明确状态。对话设置显示宿主默认值，用户主动选择后更新宿主默认值及浏览器当前会话。文本生成继续单独保存并可跟随对话模型。临时文本会话的输出路由与宿主默认值互相独立。

## 验收

- 冷启动时先打开设置，连接成功后两个菜单均列出同一宿主下可选模型和推理等级。发现目录中的条目不混入。
- 同一模型 ID 出现在多个渠道时可独立选择，保存及调用使用所选的渠道。
- 切换实例或重连时清掉过期选项，慢响应不会覆盖新目录；失败后重新进入设置可以恢复。宿主返回空目录时明确显示无可用模型。
- 打开设置不改写宿主模型。更改文本生成模型只保存其独立设置，改回跟随时清除覆盖项。
- 在候选扩展产物上验证亮色、暗色、窄屏及展开的菜单。区分真实浏览器和宿主验证、测试模型夹具及真实模型调用。
